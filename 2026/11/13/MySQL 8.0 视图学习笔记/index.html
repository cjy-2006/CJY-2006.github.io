MySQL 8.0 视图学习笔记

MySQL 8.0 视图学习笔记

用 EduCloud 的七个视图练习。建议按「先会查 → 再会写 → 然后会验算和排错」的顺序读。

1. 视图到底是什么

普通视图把一条查询保存成一个有名字的数据库对象。你可以在 FROM 里用它，像查表一样查结果。底表数据变化后，下一次查询会按当时可见的数据计算。MySQL 8.0 的普通视图没有独立保存一份可定期刷新的查询结果。

对象 适用场景
表 长期存储数据，比如提交记录
普通 SELECT 临时查看或只有一个接口用的查询
CTE（WITH） 给一条 SQL 里的中间结果起名字，方便分步骤写
视图 给多个调用者提供统一的查法，例如每人一行学习汇总
汇总表 有明确的性能需求时预先存统计值，还需设计刷新规则

建视图前先写一句话：每行代表什么，给谁查，怎么算。 同一个库有多少表，与需要多少视图无关。可复用的联查、统一统计口径、限制可见列，都是建视图的常见理由。

2. 在 Navicat 里查、建、改

先在查询窗口执行下面三条，可以分别看到视图名单、定义和数据。

SHOW CREATE VIEW 的结果里，打开 Create View 那个单元格可以看到完整定义。它返回的是定义，是否能读数据要看 SELECT 的结果。若界面没显示数据，单独执行 SELECT COUNT(*) FROM edu_auth.v_daily_active;。查询成功时，哪怕视图为空，计数也会返回一行。

动手练习。下面用独立的学习名称，在测试库先运行 AS 后的查询，确认结果，再执行创建语句。示例沿用项目库名，执行前确认连接的是测试实例。

  • CREATE VIEW 创建新视图，同名对象已经存在时会报错。
  • ALTER VIEW 修改已有视图，需要重新提供查询定义。CREATE OR REPLACE VIEW 可以创建或替换视图。改现有视图前，先保存完整定义并核对输出列、单位和调用方。
  • DROP VIEW 删除视图定义，底表数据仍在。引用这个视图的接口或其他视图可能受影响。
  • 输出列显式写名字，外部查询需要顺序时自己写 ORDER BY。定义中使用 SELECT * 时，创建时展开的列不会随底表新增字段自动扩展。

3. 汇总怎么写，最容易错在哪里

先定每行代表什么

每日活跃是一日一行，考试质量是一场考试一行，练习汇总是一人一行。这个决定通常对应 GROUP BY 的字段。日期和小时也要分清，HOUR(create_time) 只得到 0–23，跨日期的同一时段会合并。逐小时趋势需要保留日期。

两份明细先各自汇总，再合并

假设一个学生有 3 次提交、2 条练习会话。直接按学生 ID 连接两份明细会得到 6 行，每条会话重复出现 3 次。如果时长是 60 秒和 90 秒，直接求和会得到 450 秒。原版练习汇总先把两边各自聚合成每人一行，再用用户 ID 合并，得到正确的 150 秒。

用户名单可以用两边的用户 ID 做 UNION。这样只有会话或只有提交的人也能保留，再用 LEFT JOIN 带上各自统计。志愿汇总的原版以有时长的用户为起点，所以只有待审核报名的人不会出现。

把每个指标翻译成一句话

  • COUNT(*) 数行，COUNT(列) 忽略 NULL，COUNT(DISTINCT 列) 对非 NULL 值去重。用 LEFT JOIN 数明细时，数右表主键能让没有匹配的那组得到 0。
  • 通过率先确定分子和分母。按不同题目、不同用户、提交次数算，会得到不同结果。还要约定返回 0–1 还是 0–100。
  • 分母可能为 0，可以用 分子 / NULLIF(分母, 0) 得到 NULL。如果产品需要显示 0，再明确写出这个规则。
  • WHERE 先筛原始记录，HAVING 筛汇总后的组。对右表加过滤时，写在 LEFT JOIN ... ON 和写在 WHERE 的结果可能不同。后者可能把没有匹配记录的左表行去掉。

4. EduCloud 七个原版视图怎么读

视图 一行是什么 审查时看什么
edu_judge.v_user_study_summary 一名有练习会话或练习提交的用户 时长和提交分开汇总。通过率按不同题目算，范围 0–100。原版没有排除草稿。
edu_judge.v_user_exam_time 一名有考试会话的用户 session_type = '2' 才计入。场次按不同 target_id 算，同一场多次会话仍会累加时长。
edu_judge.v_problem_quality 一道有提交记录的题 通过率按人数算。原版把状态 6 算作编译错误、4 算作超时，状态码需与后端对照。
edu_auth.v_daily_active 一天 只算成功登录，排除空用户 ID，人数去重。
edu_auth.v_hourly_active 一天中的某个小时段 跨日期合并。空用户 ID 不计入去重人数，但可能计入登录次数。
edu_exam.v_exam_quality 一场考试 原版把考试学生记录数作为及格率分母，状态 2、3 算交卷。
edu_community.v_volunteer_summary 一名有时长记录的用户 按活动去重，报名状态 0 算待审核。只有报名、没有时长的人不会出现。

七个原版视图都已在本地查通。上表记录现有 SQL 的写法，业务口径和实际统计数值仍要核对。

5. 权限与常见报错

DEFINER 是定义里记录的 MySQL 账号。SQL SECURITY 决定查询视图时，用谁的权限去访问底层对象。两种模式下，查询者都需要有权查询该视图。

安全模式 谁需要有底表读取权限
DEFINER 视图定义者
INVOKER 发起查询的账号

导出里的 'edu'@'localhost' 是一个完整账号，用户名和主机部分都要对上。你本地恢复了定义者账号，并按依赖补了读取权限，所以原版视图得以查通。即使使用定义者模式，学生接口也应按登录身份约束查询范围。一个每人一行的视图本身不会自动只返回当前学生的数据。MySQL 存储对象权限

报错 先查什么
1050 同名对象已存在 用 SHOW FULL TABLES 区分表和视图。确认现有定义后，再决定使用原对象或另建学习版。
1449 定义者不存在 查视图的 DEFINER，确认准确的用户和主机名，再决定恢复账号还是调整视图权限模式。
1356 视图无效或缺权限 用 SHOW CREATE VIEW 看依赖，用 SHOW COLUMNS 核对字段，并按权限模式检查底表读取权限。
1143 字段读取被拒绝 根据错误里的账号、表和列检查授权，避免为了单个视图给整个库开权限。
1064 SQL 语法错误 先看错误位置和上一行，确认执行的是完整语句，检查从聊天复制带入的反斜杠。

6. 写入、性能与上线

  • 写入。简单视图在满足条件时可以更新底表，插入还有额外要求。含聚合、GROUP BY、DISTINCT 或 UNION 的视图不可更新。EduCloud 这些统计视图用于读，业务写入走底表。WITH CHECK OPTION 可用于可更新视图，限制经视图写入的记录符合过滤条件。MySQL 可更新视图
  • 性能。先用 EXPLAIN SELECT ... 看执行计划。MySQL 可能把视图查询合并到外层，也可能使用内部临时结果。普通视图不能直接建索引，先看底表的连接、过滤和分组。外层 LIMIT 10 只限制输出，汇总可能仍需处理许多底表记录。MySQL CREATE VIEW
  • 交付。记录视图名、每行代表什么、依赖哪些表、输出列和单位、权限模式及验证结果。用 Flyway 管理时，把后续变更放在对应服务的新版本迁移里，保留已执行脚本。

7. 三个练习

  1. 对算每日活跃。 选一个有登录数据的日期，对照下面两条。把日期换成你的实际数据日期。两边的登录次数和去重人数应该一致。
  2. 对算练习汇总。 选一个有多次提交和多条会话的学生。分别从底表算练习秒数、不同题目数、通过题目数和提交数。再看视图每列是否一致，并试着加入草稿过滤看差值。
  3. 辨认业务口径。 找一个有报名但没有时长的用户，确认原版志愿视图是否返回他。写下如果产品要求展示该用户，应该从哪些用户取并集。

查通只能证明这次查询能执行。用同一批底表数据对算，才能验证统计是否符合约定。
